# 远端大文件的滚动签名差量领取

delta-receiver 用于合作资料的本地查看和来源保存。资料对象按内容摘要保存，每次领取保留单独回执。在整份领取之外，现支持 rsync 风格的差量领取：本地就旧文件生成签名，本地模拟远端按滚动校验给出块引用与字面量，再流式重建并原子接纳。不兼容系统 rsync 命令，也不启动远端 shell，全部流程只读写本机文件与合成数据。

## 运行环境

使用 Node.js 22，无第三方依赖。首次准备执行 `npm ci --ignore-scripts`，正式运行无需下载资料或软件。全部样例使用合成数据与本机来源，不连接生产系统。

```bash
npm run check
npm test
npm run demo
```

`npm run demo` 在临时目录完成整份归档与六组差量演练，实际统计传输量，退出时清理临时内容，正常应在数秒内结束。

## 差量协议

协议版本为 1，弱校验为可按字节滚动的 Adler-32，强摘要为 SHA-256（签名中每块保存前 16 字节前缀，整份新文件在结束帧给出完整 64 字符摘要）。允许的块大小为 8、16、64、256、1024、4096 字节，选块策略把块数控制在 256 块以内，使弱索引和签名体积随块数而非文件大小增长。

**签名（本地旧文件 → 二进制）**：魔数 `DSIG` + JSON 头部 + 每块 22 字节定长记录（弱校验 4、块长度 2、强摘要前缀 16）。头部说清协议版本、块大小、弱/强算法、旧文件大小与旧文件 SHA-256 身份、块数量。

**差量帧（本地模拟远端 → 重建端）**，每帧为 `类型(1) + 载荷长度(4) + 载荷 + 长度回写(4)`：

- 头部帧：与签名逐项对应的块大小、弱校验、强摘要、旧文件身份与块数量；重建端先核对，不符即拒绝。
- 字面量帧：无法匹配的原始字节，单帧受 64 KiB 上限约束。
- 引用帧：签名中的块索引（uint32）；重复块复用同一索引，重复块天然只占一帧。
- 结束帧：新文件完整 SHA-256 与新文件大小，作为整份重建的最终核验依据。

## 安全与正确性保证

- **滚动而非同偏移分块**：窗口按字节滑动并用 O(1) 滚动弱校验更新，头部插入一个字节后后续匹配块仍能逐个命中。
- **弱碰撞不出错**：弱校验只做筛选，命中候选后必须再通过强摘要前缀比对；已知 Adler-32 碰撞对（`ACAAAAAA`/`BABAAAAA`）会被否决并退化为字面量。
- **重复块与尾部短块**：弱索引按弱值成组、重复块保留最低索引；不足一个块大小的尾部按等长短块单独匹配，长度与强摘要双重约束。
- **基底替换即失效**：重建前核验基底大小与 SHA-256 身份，每次引用前复核 inode/大小并对引用块重算强摘要；基底被替换则已收到的引用立即作废。
- **远端换版即中止**：文件版生成在收尾复核大小与 inode，变化即报 `REMOTE_CHANGED`，不继续拼接。
- **输出不覆盖基底**：重建只写入隔离暂存件（`.tmp`），整份 SHA-256 与结束帧核验通过后才 `rename` 为内容对象；任何失败都清理暂存件且不登记回执，失败文件不会成为下一次的可信基底。
- **内存受控**：签名流式生成；匹配端只保留定长环形窗口（一个块）、有界字面量缓冲（64 KiB）和块索引；重建端不缓存整份文件。

## 资料操作

```bash
npm start -- inspect fixtures/base.bin
npm start -- capture fixtures/base.bin .local/archive
npm start -- list .local/archive

# 差量领取三步
npm start -- sign fixtures/base.bin base.sig
npm start -- delta fixtures/base.bin fixtures/new.bin new.delta base.sig
npm start -- apply-delta fixtures/base.bin new.delta base.sig .local/archive
```

`sign` 生成紧凑二进制签名；`delta` 本地模拟远端产出差量帧并打印签名、差量与全量的实际字节对比；`apply-delta` 流式重建、整份校验后原子接纳，回执 `mode` 为 `delta` 并记录引用数、字面量字节与线上字节。小文件因每帧九字节开销可能不省字节，百兆级且只改小段的成果文件节省比例随文件增大而显著（演练中 1.2 MiB 文件节省约 99%）。

`capture` 只表示来源字节已保存，不声称领域流程已自动完成。`scripts/create-fixtures.js` 用于维护者重建合成资料；运行与测试直接读取已提交的资料。

## 演练场景（npm run demo）

1. 头部插入一字节：验证错位后滚动匹配仍命中后续全部块，字面量仅 1 字节。
2. 中段小改动：验证只有改动邻域退化为字面量。
3. 弱校验碰撞：碰撞窗口走字面量，重建字节与摘要仍正确。
4. 故意改动基底：同大小不同内容，以 `BASE_MISMATCH` 拒绝，无暂存残留、无回执。
5. 远端生成期间换版：以 `REMOTE_CHANGED` 中止。
6. 失败后重试：恢复正确基底后成功，证明可信基底来自被核验的原文件而非失败暂存件。

## 目录约定

- `src/checksum.js`：Adler-32 弱校验与 O(1) 滚动更新。
- `src/delta.js`：签名生成与二进制编解码、滚动匹配器、帧协议、流式重建与原子接纳前置校验。
- `src/archive.js`：内容对象、来源回执与完整性检查，含差量接纳入口 `acceptDelta`。
- `src/domain.js`：领域读取、查看接口与差量能力登记。
- `src/cli.js`：命令行入口与六组演练编排。
- `fixtures/`：本地资料与领域协议配置。
- `test/`：已有行为与差量行为的运行验证，使用独立临时目录。

## Linux 环境

Dockerfile 使用 Node.js 22 镜像。可执行 `docker build -t delta-receiver:local .` 后运行 `docker run --rm --network none delta-receiver:local npm test`。测试中的文件读写都限定在临时目录与回环本地路径，不需要外部网络。构建阶段准备依赖，运行时不安装依赖。
